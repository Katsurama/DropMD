# 交接说明

长期规则见根目录 `CLAUDE.md`。这里记录当前进度、待办和已知问题。

## 当前状态

- 2026-10-26 准备公开：仓库删除后重建，历史只从一个新的初始提交开始，版本号从 **0.1.0-beta.1** 重新开始，默认分支 `main`。
- 公开仓库的 App 内更新不需要令牌（私有仓库的令牌功能已去掉）。
- 发布：`tools/build_local.sh vX.Y.Z-beta.N` 在本机构建并发布；或在 GitHub Actions 手动运行“构建 DropMD”并填写 `release_tag`（公开仓库的 Actions 不计分钟数）。

## 结构要点

- 单页（`Rich*`，TextKit 1）与双页（原文 + `Resources/preview` 预览）都保存为标准 Markdown；编辑器不认识的内容原样保留。
- Markdown 解析是自己写的（`MarkdownCodec` 等，只依赖 Foundation），`tools/test_codec.sh` 做往返测试。
- 提示框（`> [!NOTE]` 等，`MDCallout`）的标题行作为原样文字保存，前面自动空行以免与上一个引用相连。
- 软件更新：查询 GitHub Releases → 下载 zip（没有 zip 时用 dmg）→ 校验 SHA-256 → 解压到 App 旁边的 `.DropMD-update.app` 并检查包名、版本 → 用户点“重新启动”后由后台脚本替换并重新打开（`AppUpdateInstaller`，`tools/test_update.sh` 测试）。App 所在位置不能写入时退回“打开安装包、手动拖”。刚更新完时，把“下载”里的旧安装包移到废纸篓。
- 更新来源（owner/repo）不写在源码里：构建时由 `GITHUB_REPOSITORY`（GitHub Actions 自带；本机由 `build_local.sh` 从 git 远程地址取得）写入 Info.plist。
- 图标是 Icon Composer 格式（`macos/Resources/AppIcon.icon`），在本机用 `macos/make_icon.sh` 预先编译到 `AppIcon.compiled`：GitHub 构建机上 Xcode 26 的 actool 编译它会崩溃。
- Xcode 27 的新编译方式会把程序的 SDK 版本记成 14，Liquid Glass 不启用：`build_app.sh` 在支持时加 `--build-system native`，并在 SDK 低于 26 时报错。
- 发布的程序里不能有本机路径：`build_app.sh` 用 `-file-prefix-map` 把源码路径换成相对路径。

## 待办 / 需要用户决定

1. Markdown 解析可以考虑换成苹果的 swift-markdown，但高亮、脚注、公式、下划线、折叠块仍需额外处理，尚未决定。
2. 还没有在真机上手动验证：粘贴时的格式清理、单页导出 PDF / HTML、用真实中文输入法打字时的自动格式。
3. 已知限制：单页中公式显示为文字，折叠块总是展开；文末脚注说明行开头的编号也显示为上标；单页里提示框的标题行显示为 `[!TIP]` 原文。

## 用户的偏好

- 面向普通用户：像 Word / Pages 一样不用写代码，界面按苹果自带 App 和 Xcode 的标准设计。
- 文字要短，不要冗长的说明。
- 不单独发安装包，直接发布新版，用户在 App 内升级。
